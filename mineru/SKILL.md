# MinerU 输出整理

核心工作不是"转格式"，是**把 MinerU 丢掉的信息捡回来，同时不给原文添字**。

## 一个必须先知道的事实

**`full.md` 是残缺品，不要拿它当底稿。** MinerU 把页眉、页码、脚注标记为 `is_discarded`，`full.md` 直接扔了——一篇 12 页论文可能因此丢 60 条脚注，一本 200 页的书丢 300 条。

**`layout.json` 是唯一可靠的正文来源**（只有它保留行级 spans），`block_list.json` 用来取跨页合并关系，`full.md` 只作对照。细节见 `references/mineru-outputs.md`。

脚本一律把报告写成 UTF-8 文件、stdout 只打一行 ASCII——Windows 控制台是 GBK，中文直接 print 会变乱码。**用 Read 工具读报告文件。**

## 流程

### 0. 探查与审计

```bash
python <skill>/scripts/probe.py <目录>
```

产出 `_probe.txt` 和 `_markers.tsv`。**这一步是整个流程里最值得花时间的地方。** 报告里 `[检查]` 段会自动报出六类已知坑：句内枚举圈码、被误判成脚注的编号列表、漏合并的跨页段落、扁平的标题层级、篇幅截断、OCR 误判的公式记法。逐条核对，别跳过。

圈码数与脚注数对不上时**停下来**，读 `_markers.tsv` 找出哪些圈码不是脚注引用。

### 1. 重建骨架

```bash
python <skill>/scripts/build.py <目录> -o _skeleton.md [--skip-marker 12,30]
```

`--skip-marker` 传上一步认定为非脚注的圈码全局序号。骨架已经处理好脚注编号、页码锚点、跨页合并、图表、标题层级（源里层级扁平时按编号形态重建）。

`<!--?quote-->` / `<!--?center-->` 是待你确认的缩排/居中块，依据只是 bbox，**必须对着文字复核**，处理干净否则 `verify.py` 会拦下来。

### 2. 标点：先判断，再问用户

`probe.py` 报的「标点完整度」决定这活的量级。

**比值 ≥ 0.05（标点完好）**：骨架基本就是成品。**这时不要重新输出正文**——在骨架上做定点 Edit（改标题层级、删复核标记、补 frontmatter）就行，200 页也很快。

**比值 < 0.02（标点大面积丢失）**：先裁一块图确认成因：

```bash
python <skill>/scripts/crop_pdf.py <origin.pdf> --page 0 --rect 85,220,509,270 -o probe.png
```

图里标点清清楚楚而提取出来是空格 → PDF 文字层的 Unicode 映射坏了。**这时必须问用户走哪条路，并按页数给推荐：**

- **< 20 页** → 推荐「读原图还原」：逐页裁图，照着原件写标点。实测 12 页约耗时 30 分钟。
- **≥ 20 页** → 推荐「剥文字层重跑 OCR」：`crop_pdf.py --strip-text-layer -o 无文字层.pdf --dpi 300`，用户把它喂回 MinerU。要用户多跑一次，但拿到的是**原文标点而非推断**，且耗时不随页数爆炸。

把两种代价说清楚，让用户选。**不要默认走"模型推断标点"**——那是三条路里唯一不可信的。

脚注按约定**只清标签、不补标点**（多为书目著录，补标点等于改引用格式）。

### 3. 校验与交付前 diff

```bash
python <skill>/scripts/verify.py <成品.md>
python <skill>/scripts/diff_report.py <目录> <成品.md>
```

`diff_report.py` 剔除标点、空格、Markdown 语法后逐字符比对，剩下的就是实质改动。**这一步不可跳过**：曾有一次标点规范化脚本的正则分组 bug 静默删掉了约 85 处括号内容，全靠它揪出来。

**改动报告必须由脚本生成，不能靠回忆。** 凭印象列一定会漏，漏掉的往往正是最该报告的那条。

## 两个必须问用户的决策点

**一、标点路线**（见上）。

**二、疑似脱字 / errata**。看到正文少字（少个「的」「在」「中」）或明显笔误时：

1. **默认不动**，先把清单列给用户：位置、原刊原文、疑似应为、判断依据
2. 列之前**先裁图核实**——分不清是原刊印错还是 MinerU 认错，就没资格提这个建议
3. **用户许可的才写进正文**，同时在校注文件记录原刊字样与位置
4. 用户未许可的、存疑的，只留在校注文件里

## 交付物

**论文**：单个 `.md`。
**图书**：索引 + 分章，**不要再叠一份全书**——同一段文字存两份会在检索时同时命中、挤占名额，两份还会漂移；需要整本时 `cat` 一下即可。

```
中国近现代史.md              索引：书目元数据 + 完整目录 + 各章链接与页码范围
01-第一章 ….md               正文 + 本章脚注（按章重编号），frontmatter 标明书名/章名/页码范围
02-…
中国近现代史.AI校注.md        全书唯一一份校注，内部按章/页分节
```

脚注按章重编号很关键：正文和它的注在同一个文件里，检索到某段时注能被一起召回；否则 `[^47]` 的定义在几万字之外，AI 看到的是空引用。

每章 frontmatter 写清出处（书名、章名、对应印刷页码），让每个片段自描述。页码锚点 `<!--p.108-->` 保留，它让 AI 能给出可核对的引用。

**校注单独成文件**，不要放进正文——正文文件会被喂给 AI，校注混在里面会被当成内容检索到。

`tags` / `aliases` / `cssclasses` 是 Obsidian 内置属性，**键名必须英文**，改中文就退化成普通文本、丢掉功能。其余自定义字段可以用中文。

模板见 `references/templates.md`。

## 红线

**一、不给正文补字。** 学术文献以原刊为准。用户可能引用这份文档，你补的字会变成他引文里的错误。要改，走上面的决策点二。

**二、改动原文前先核 PDF 原图。**

```bash
python <skill>/scripts/crop_pdf.py <origin.pdf> --page 2 --rect 65,545,300,559 -o crop.png
```

坐标用 `layout.json` 的 bbox，裁完用 Read 工具看。曾有一处正文写「秦令（11）」而内容明显对应「秦令（10）」，裁图一看**原刊就是这么印的**——于是保留原样加校注，而不是"改对"。

**三、所有内容层改动都要主动告诉用户。** 标点可以概括成一句；**动了字的必须逐条写明位置、原文、改后、依据**。用户没问不等于不用说。报告按重要度排序：内容改字 → 内容补入 → 结构判定 → 标点格式 → 位置迁移。

## 别做的事

- 别把 `full.md` 当底稿改（脚注已经没了）
- 别用 `content_list*.json` 做正文源（断行处数字会粘连）
- 别在标点完好时重新输出正文（改骨架就行）
- 别在没跑 `diff_report.py` 的情况下说"整理完成"
