# 编目：分类法层级规则（祖先链必须写满）

> 核验日期：2026-08-02。证据取自线上 `mulu.1012.wiki` REST 与代码仓 `D:\projects\mulu1012`。

## 一句话规则

WordPress **不会**因为你挂了子项就自动挂上父项。本站约定：**挂哪个词，就把它到根的整条祖先链全部显式挂上**。

## 为什么不自动

层级关系与归属关系存在两张表里，互不影响：

- `term_taxonomy.parent` —— 词与词之间的父子关系
- `term_relationships` —— 题录 ↔ 词，只记录**实际赋予**的那个词

无论经典编辑器复选框、区块编辑器层级选择器、REST API 还是 `wp_set_object_terms()`，都只写你给的那几个词。本站两套导入实现也都一样——沿路径逐级 `term_exists`，但 `$term_id` 每轮被覆盖，**只返回最后一段**，随后以 `wp_set_object_terms( $post_id, $ids, $taxonomy, false )` 写入：

- `mulu-database-importer/includes/class-mdi-catalog-import-service.php:305-336`（`resolve_term_path`）、`:368`
- `mulu1012-suite/includes/Modules/CatalogImport/TaxonomyResolver.php:146-168`（`materialize_path`）、`Service.php:464`

也就是说路径 `A>B>C` 只会挂上 `C`。这不是某一版的实现细节，两版行为一致。

## 涉及哪些分类法

`sites` 上只有 4 个层级分类法，规则只对它们生效：

| REST 名 | 中文名 | 层级 | 备注 |
|---|---|---|---|
| `site_catalog` | 主分类与特色史料 | ✅ | 最深 4 级，87 个词，主战场 |
| `site_type` | 站点类型 | ✅ | 受控，导入不得新建词 |
| `xilie` | 系列 | ✅ | |
| `authorized_institution` | 已授权机构 | ✅ | |

其余 `special_history`、`research_topic`、`period`、`geo_scope`、`material_type`、`material_language`、`digital_format`、`site_scope`、`access_type`、`zhubanzhe`、`tier` 全是**扁平**分类法，不存在这个问题。

核验命令（分类法增删后请重跑）：

```bash
curl -s "https://mulu.1012.wiki/wp-json/wp/v2/taxonomies" | python -c "import json,sys; [print(v['rest_base'], v['name'], v['hierarchical']) for v in json.load(sys.stdin).values() if 'sites' in (v.get('types') or [])]"
```

## 线上既有数据就是这么挂的

抽查 `site_catalog=3114`（点校古籍库，路径 `中国史数据库>中国古代史库>电子古籍库>点校古籍库`）下的题录：

| 题录 ID | `site_catalog` |
|---|---|
| 12066 | `[3018, 849, 3114, 5765]` |
| 12065 | `[3018, 3114, 849, 5765]` |
| 11948 | `[849, 3018, 3114, 5765]` |
| 11949 | `[849, 3018, 3114, 835, 5765, 527]` |

3018 = 中国史数据库，849 = 中国古代史库，5765 = 电子古籍库，3114 = 点校古籍库 —— **四级全挂**。11949 同时挂了第二条链（835 中国近代史库 > 527 近代综合史料库），说明多条链并存时**每条都要各自挂满**。

术语的 `count` 字段只统计直接归属，不含子孙。线上 `中国史数据库` count=659、`中国古代史库` count=405，正是祖先链被写满的结果；若改成只挂叶子，这些数字会塌到 0，前台分类树的计数全线失真。

## 怎么写

走 `mulu1012-catalog/import-sites-batch` ability。它的 `taxonomy_terms` 收的是**路径数组**，分隔符 `>`（按 `/\s*>\s*/u` 切分，最多 5 段）。由于一条路径只挂叶子，**祖先链要拆成多条路径分别列出**：

```json
"taxonomy_terms": {
  "site_catalog": [
    "中国史数据库",
    "中国史数据库>中国古代史库",
    "中国史数据库>中国古代史库>电子古籍库",
    "中国史数据库>中国古代史库>电子古籍库>点校古籍库"
  ]
}
```

❌ 错误写法（只挂上叶子，父项全丢）：

```json
"site_catalog": ["中国史数据库>中国古代史库>电子古籍库>点校古籍库"]
```

❌ 同样错误（缺路径前缀，见下节"同名歧义"）：

```json
"site_catalog": ["中国史数据库", "中国古代史库", "电子古籍库", "点校古籍库"]
```

注意 `taxonomy_terms` 每个分类法上限 20 条路径（schema `maxItems: 20`）。4 级链 × 多条并存链容易逼近上限，超了要削减挂载的叶子数量，而不是省略祖先。

另外 `site_type`、`site_catalog`、`access_type`、`geo_scope` 四个分类法是**必填**，缺任何一个整条报 `mdi_missing_taxonomy_terms`（`class-mdi-catalog-import-service.php:196`）。

## 坑一：路径前缀是唯一的定位手段，写错会静默建词

`resolve_term_path` 按 `term_exists( $name, $taxonomy, $parent )` 在**指定父项下**逐级找词，找不到就 `wp_insert_term( $name, $taxonomy, array( 'parent' => $parent ) )` 直接建（`class-mdi-catalog-import-service.php:318-326`）。这里**没有**同名歧义检查，也**没有**受控分类法白名单——写错一个字不会报错，只会在那个父项底下多出一个新词，回执 `created_terms` 里才看得到。

所以：**每次导入必须读回执的 `created_terms`**，凡是本该复用却出现在新建列表里的，都是写错了，要立刻停下来核对，不要继续跑后续分片。

线上已经有一批根级重复词，与正规路径下的同名词并存：

| 中国近代史库 | 7502 | 0 | `中国史数据库>中国近代史库` (835) |
| 世界现代史库 | 7475 | 25 | `世界史数据库>世界现代史库` (3021) |

产生机制见下节——不是「历史遗留」四个字能带过的，同一个口子现在还开着。

## 坑二：`mulu_taxonomy_terms` 不能用于层级分类法

[`wordpress-json-upload.md`](wordpress-json-upload.md) 推荐的另一条通道——`POST /wp/v2/sites` 带 `mulu_taxonomy_terms` 参数——**只收词名，不支持路径**，且（`mulu-database-importer/includes/class-mdi-taxonomy-resolver.php:66-80`）：

- 查词用 `term_exists( $name, $taxonomy )`，**不传 parent**，同名词存在多个时命中哪个不确定
- 后台开关「自动创建分类项」打开时，建词用 `wp_insert_term( $name, $taxonomy )`，**不传 parent → 一律建在根级**
- 开关关闭时词不存在则报 `mulu_import_missing_term`

这条通道从原理上就挂不出层级关系，也正是根级重复词的成因。**层级分类法（`site_catalog`、`site_type`、`xilie`、`authorized_institution`）一律走 ability 的 `taxonomy_terms` 路径语法，不要用 `mulu_taxonomy_terms`。** 扁平分类法用它没问题。

## 坑三：不要指望 `include_children` 兜底

WordPress `WP_Tax_Query` 的 `include_children` 对层级分类法默认为 `true`，父项归档页确实能列出子项题录。但本站有三处不吃这套：

- REST `?site_catalog=<父ID>` 走 `category__in` 语义，`include_children => false`，**查不到只挂叶子的题录**
- 术语 `count` 不含子孙（见上）
- 前台"按分类筛选"依赖 `site_catalog` 的直接归属与计数

`mulu-auto-subcategory-rules` 插件用 `term_is_ancestor_of()`（`includes/class-masr-plugin.php:1005,1027`）自行判定祖先，只覆盖它自己的自动打标规则，不改写题录的归属，**不能当作祖先链的替代**。

## 采集阶段该做什么

采集阶段 `site_catalog` 等编目字段**仍然留空**（见 SKILL.md 第 5 步），本规则在编目阶段生效。采集阶段唯一相关的动作是：把源站原始标签按 `来源名｜分类法名：值` 原样存进批次总目末列的「备注」，作为日后映射主分类的证据。

## 上传前自检

- [ ] 层级分类法走 ability 的 `taxonomy_terms`，没有用 `mulu_taxonomy_terms`
- [ ] 每个层级分类法的每条挂载链，从根到叶逐级都在 `taxonomy_terms` 里出现
- [ ] 每条路径都写全前缀，没有裸词名
- [ ] 必填四项 `site_type` / `site_catalog` / `access_type` / `geo_scope` 都有值
- [ ] 单个分类法的路径条数 ≤ 20
- [ ] 扁平分类法没有误用 `>`（会报「非层级分类法不能使用路径」）
- [ ] 先小批试跑，**逐条核对回执 `created_terms`**——不该新建的词出现在里面就停下

| | `mulu-database-importer` | `mulu1012-suite` |
|---|---|---|
| 入口 | ability `mulu1012-catalog/import-sites-batch` | `POST /mulu1012/v1/catalog-import/preflight` + `/apply` |
