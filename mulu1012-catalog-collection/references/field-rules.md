## 1. 总规则

- 37 项顺序固定，不增删、不改名。
- “必填”表示必须尽力搜索。客观不存在或可靠来源没有提供时允许留空，但必须在 AI 填充评语中说明。
- “选填”按实际来源填写，不推测、不编造。
- `文章ID`由 WordPress 发布后生成，本地新候选和上传阶段保持为空。
- `评级`由人工填写，AI 保持为空。
- 完全由 AI 搜集的条目，上传后作者使用工作台配置的指定 AI 用户。
- 每个非空字段必须有字段级依据；每个空字段必须有未填原因。
- `batch.json`中上传给 WordPress 的`contract_version`和`contract_hash`使用 WordPress 37 表头契约；本 Skill 的填写规则另用`classification_contract_version`和`classification_contract_hash`记录。

## 3. 摘要

直接说明资源收录什么、覆盖什么时间或地区、提供何种访问形态以及访问限制。

- 使用“汇集、收录、提供”等明确动词。
- 不重复“XX数据库是一项……的数据库”。
- 不添加“……的功能”等空泛表述。
- 免费与授权并存时，同时说明哪部分免费、可直接访问，哪部分需要机构授权。
- 不把无法从来源确认的数量、年代、机构或访问范围写入摘要。

示例：

> 汇集1900年至1949年在中国、日本及朝鲜半岛出版的约1,200种中文、日文报刊，提供全文检索和原刊影像浏览。题录检索和部分样张可直接访问，报刊全文及高清影像需机构授权。

## 4. 正文与官网介绍

`摘要`、`正文介绍`和`官网介绍`是三个不同字段：

- `摘要`是编目者写的简短中文概述。
- `正文介绍`是完整官网介绍的中文呈现，或没有官网介绍时由 AI 据可靠来源写成的较完整说明。
- `官网介绍`是官网原文档案，必须保存完整主要正文。

### 4.1 定位真正的介绍页

进入官网后继续查找：

- `About`、`About us`、`Presentation`、`Project`、`Introduction`。
- `À propos`、`Présentation`、`Über`等其他语言的同类页面。
- `关于`、`项目介绍`、`数据库简介`、`数据库说明`、`建库缘起`、`帮助`。

依次检查导航、页脚、站内搜索、站点地图和项目链接。存在专门介绍页时：

- `introduction_url`填写专门页面，不填首页或检索入口。
- `entrance_url`继续填写实际使用、检索或浏览资源的入口。
- 搜索引擎摘要、meta description、首页卡片和机构目录短句不得作为官网介绍。

### 4.2 官网介绍的完整性

`official_introduction`保存介绍页中与项目有关的完整主要正文。规则如下：

- 从介绍正文的第一个标题或第一段开始，保存到正文结束。
- 保留项目背景、目标、内容范围、方法、使用说明、链接说明、更新计划、作者、贡献者和联系信息；这些内容位于介绍正文时不得删去。
- 保留原文语言和页面顺序。双语或多语页面保存全部语言版本，不只保留其中一段。
- 保留 Markdown 标题、段落、粗体、斜体、链接、列表、表格、引用、脚注、图片说明和必要图片链接。
- 相对链接转换为可访问的绝对链接；链接文字和强调格式不得丢失。
- 只删除网站导航、面包屑、Cookie 提示、重复移动菜单、通用页脚、广告和与项目无关的推荐内容。
- 不设“适合 Excel”的人为字数上限，不得因页面很长而缩写、改写或抽取代表性段落。
- 介绍分布在多个正式页面时，完整保存每个相关页面，在字段中使用`## 页面名称`分隔，并在`official_source`逐条列出来源。

`evidence.jsonl`中的`excerpt`只是支持字段判断的短摘录，绝不能复制到
`official_introduction`充当全文。

### 4.3 正文介绍

有官网介绍时：

- 官网是中文：`body_introduction`保存完整中文主要正文，允许统一空行和标题级别，不得删减内容。
- 官网是外文：第一行写`译自官网`，随后完整翻译官网介绍主要正文，保留与原文对应的 Markdown 结构和链接。
- 页面有内容重复的平行双语版本时，`official_introduction`仍保留全部原文；`body_introduction`选择信息最完整的一种语言完整翻译一次，并说明原页为双语页面。
- 不得依据一句摘要、搜索片段或首页宣传语扩写正文。
- `body_source`和`official_source`均写“页面名称 + 超链接”；多来源逐条列出。

例如，沦陷区中国人物传记辞典：

```text
entrance_url: https://bdoc.enpchina.eu/
introduction_url: https://bdoc.enpchina.eu/presentation/
```

其`official_introduction`应从`Projet/*Project*`开始，完整保留法文、英文、
`Auteur/*Author*`、作者与网站设计者信息、`Contact`及正文中的 Markdown 链接，
不能只保存首页的`A database from ENPChina Project`。

### 4.4 没有官网介绍

- 只有在检查官网导航、站点地图、帮助页和建设机构页面后仍不存在介绍页，才判定“没有官网介绍”。
- `official_introduction`和`official_source`留空。
- `body_introduction`第一行写：`本介绍由AI生成`。
- 综合多个可靠来源写较完整中文介绍，不加入来源没有的信息。
- 在正文中使用 Markdown 脚注标出来源，著录遵循 `GB/T 7714-2025`。
- 若介绍页可能存在但因登录、反爬、脚本渲染或文件损坏无法取得全文，标记阻断，不得按“没有官网介绍”处理。

示例：

```markdown
本介绍由AI生成

该资源汇集……，覆盖……，由……建设。[^1] 目前提供……；其中……可以直接访问，……需要机构授权。[^2]

[^1]: 机构名. 页面或文献题名[EB/OL]. URL, 引用日期.
[^2]: 机构名. 页面或文献题名[EB/OL]. URL, 引用日期.
```

## 5. 授权判定

可确认授权的依据：

- 机构或图书馆官方购买、订购、正式开通页面。
- 仍在有效期内的官方试用通知，并记录截止日期。
- 官方访问说明明确校内 IP、VPN、读者证、馆内或馆外访问范围。

普通论文提及只能作为继续核验的线索，不能单独确认当前授权。过期试用不计当前授权。

每条授权记录保存：

- 机构或图书馆正式名称。
- 授权状态、访问范围、授权内容。
- 截止日期和核验日期。
- 依据页面名称与 URL。

`field-fill.jsonl`使用结构化对象；生成审核包时，XLSX 和
`wordpress-upload.jsonl`按固定顺序序列化为多行文本，使 Excel 与
WordPress 工作台显示一致。

## 6. AI 填充评分与评语

字段生成 AI 不得自评。独立 AI 按可靠性给出 `0-100` 总评分。

独立审核必须额外检查：

- `introduction_url`是否为专门介绍页，而不是首页或检索入口。
- `official_introduction`是否明显只是搜索摘要、meta description或证据短摘录。
- 官网介绍的标题、段落、双语内容、链接、作者和联系信息是否完整。
- `body_introduction`是否覆盖完整原文，而不是摘要式翻译。
- `site_type`是否只使用网站、数据库、母库、子库、独立库之一，并由产品结构支持。
- `primary_category`是否表示主要史料内容或功能，而不是机械重复站点类型。
- `featured_sources`是否为具体、可核验的独特史料亮点，而不是宽泛材料名。
- `database_type`是否只在综合库、专题库、知识库三项中判断，没有默认填专题库，也没有把拟新增词写入字段值。
- 无法判断完整性时必须列为阻断项，不得给绿色状态。

每个非空字段使用以下格式：

```markdown
### 主办者（92/100）

- **填充值：** 浙江大学数字图书馆
- **依据：** “本数据库由浙江大学图书馆建设并维护……”
- **来源：** [项目介绍](https://example.org/about)
- **方式：** 直接提取
- **判断：** 页面明确说明建设和维护主体，使用机构正式全称。
```

规则推断字段写明规则：

```markdown
### 站点类型（88/100）

- **填充值：** 子库
- **依据：** 页面将该资源列为“XX母库”的专题子库，并提供独立检索入口。
- **来源：** [数据库说明](https://example.org/database/info)
- **方式：** 规则推断
- **判断：** 同时满足母库从属关系和独立检索入口，判为子库。
```

空字段写明原因：

```markdown
### 上线时间（未填）

- **原因：** 官网、建设机构页面和检索到的项目论文均未提供首次上线时间。
- **已核来源：** [官网](https://example.org)、[项目论文](https://example.org/paper)
```

拟新增词项写明：

```markdown
### 拟新增词项

- **分类法：** 研究主题
- **词项：** 德国犹太史
- **依据：** 数据库说明明确以德国犹太社群、组织与文献为主要内容。
- **来源：** [About](https://example.org/about)
- **判断：** 现有规范词中没有同义项，拟在人工批准时创建。
```

评语末尾汇总：

- 总评分与理由。
- 阻断项。
- 建议状态。
- 本条所有未填字段。
- 本条所有拟新增词项。
