## 1. 任务定义

在 `batch.json` 固定：

- 任务名称、主题、目标和目标独立候选数量。
- 语言、资源类型、纳入规则、排除规则、优先来源和证据要求。
- 批次 UUID、字段契约版本、创建时间。
- 用户另行指定的范围限制。

“目标数量”只计算最终确认独立的新候选：

- `fillable`、已完整填充但有资料阻断的独立项：计数。
- `duplicate`：不计数。
- `suspected_duplicate` / `needs_human_dedup`：不计数。
- 与主题无关或没有足够信息判断是否为目标资源：不计数。

## 2. 搜索与检查点

按来源质量优先搜索：

1. 数据库官网，以及 `About`、`Presentation`、`Project`、`À propos`、`Über`、`关于`、`项目介绍`、`数据库说明`、`建库缘起`等专门介绍页。
2. 建设机构、大学、研究所、图书馆或档案馆的正式页面。
3. 可靠的数据库目录、学术论文、项目论文、新闻稿、馆藏指南。
4. 其他能够真实介绍该数据库的来源。

“索引来源”是实际发现条目的页面、论文或目录，不是搜索引擎结果页。

进入候选官网后必须继续定位专门介绍页：

- 检查首页导航、页脚、站内搜索、站点地图和帮助页。
- 优先保存具体项目介绍页作为 `introduction_url`；首页或检索入口只在确实没有专门介绍页时使用。
- 搜索结果摘要、HTML meta description、首页卡片文案和机构目录的一句话说明只能用于发现与交叉核验，不能代替官网介绍全文。
- 页面由 JavaScript 渲染、藏在 PDF 或需要交互时，改用浏览器、PDF 解析或其他能够取得完整主要正文的方式；仍无法取得时标记阻断，不得用短摘录冒充全文。

每累计 20 至 30 条新候选执行内部检查点：

1. 规范化名称、别名、入口 URL、介绍页 URL。
2. 用 `local-dedup.py` 与本任务全部候选互重。
3. 把未被本地重复排除的候选交给线上批量 Ability。
4. 保留裁决、匹配项、分数和逐项依据。
5. 继续搜索，直到独立候选达到目标并保留 10% 至 20% 的搜索缓冲。

达到搜索目标后，对全任务候选统一执行一次完整查重。最终独立数不足时继续补搜，不降低主题相关性或查重标准。

## 3. 查重裁决

### 程序预筛

- 最高分 `>=90` 且至少有两个强信号：`duplicate`。
- 最高分 `55-89`：`suspected_duplicate`，交给 AI 深审。
- 最高分 `<55` 且没有强信号：`fillable`。
- WordPress 文章 ID 完全相同可直接判重。

强信号包括规范化入口 URL、规范化介绍页 URL、规范化正式名称、主办者和稳定母库关系。名称、同机构或同域名中的任何一个信号都不能单独判重。

### AI 深审

- `90-100/100`：重复。
- `50-89/100`：待人工判重。
- `0-49/100`：独立。
- 关键证据不足：暂停并标记阻断。

AI 必须同时写：

- 支持重复的证据。
- 支持独立的反证。
- 最终结论和置信度。

### 关系判断

- 改名、换域名、镜像站、迁移站点仍可属于同一题录。
- 共享平台上的不同子库不能仅因域名相同判重。
- URL、名称和内容范围共同明确命中时可直接判重。

## 4. 填充与独立审核

只对 `fillable` 候选执行完整 37 项填充。

外文资源：

- 有官方中文名时使用官方中文名。
- 没有官方中文名时生成准确、简洁的中文标题。
- 原文名、简称、缩写和其他常见译名统一写入“别名”。

正文与官网介绍：

- 先完成官网介绍全文采集，再写摘要和正文介绍。
- `official_introduction`保存专门介绍页完整主要正文及原始 Markdown 结构；不得摘要、截断、改写或只保存代表性段落。
- `body_introduction`对完整官网介绍作忠实中文呈现。外文页面完整翻译，中文页面完整保留；摘要字段仍单独保持简短。
- 页面存在平行双语版本时，官网介绍保留页面上的全部语言与原顺序；正文介绍选择信息最完整的一种语言完整翻译一次，避免重复翻译同义段落。
- 介绍内容跨多个正式页面时，逐页完整保存，用二级标题标明页面名称，并在来源字段列出全部 URL。
- 完整 Markdown 同时保存到`field-fill.jsonl`；必要时在`evidence/`保留原文 Markdown 快照。证据记录中的`excerpt`只是字段依据短摘录，不能反向替代官网介绍字段。

字段生成 AI 完成后，由另一个独立 AI 审核：

- 总评分衡量信息可靠性，不衡量填满程度。
- 客观不存在的字段可留空，不因留空直接扣分。
- 每个阻断项写明影响、需要补什么和建议处理状态。
- `评级`始终留给人工。
- 把介绍页未定位、官网介绍疑似短摘录、正文介绍未覆盖完整原文、Markdown 结构丢失列为阻断项。

## 5. 母库和系列

- “系列”是可多选分类信息。
- “母库”是直接母库的稳定题录关系，允许为空。
- 没有母库不是缺陷，也不是阻断。
- 只有来源明确说明存在母库，但无法对应到正式题录 UUID 时，才标记 `parent_unresolved` 阻断。
- 不把普通栏目、同一机构、同一平台或相似名称推断为母库。

## 6. 上传与回读

上传前必须满足：

- 用户已明确确认上传。
- `validate-batch.py` 通过。
- `verify-review-package.mjs` 通过。
- `upload-manifest.json` 与 `wordpress-upload.jsonl` 校验和一致。

上传行为：

- 一个任务只创建一个 WordPress 批次。
- 每片最多按 Ability 上限提交；片段只用于传输。
- 批次 UUID、候选 UUID、版本 UUID、证据 UUID、审核 UUID 和幂等键沿用本地值。
- 正式库修订号与最终查重时相同且算法版本相同时，复用查重结果。
- 修订号或算法版本变化时，只重查本次上传中缓存已过期的候选。
- 每条候选独立返回成功或失败；失败项可用相同幂等键重试。

回读核对：

- 工作台批次总数等于本地总候选数。
- 各状态数量一致。
- 每条成功项的 UUID、37 项字段、证据、查重和审核一致。
- WordPress 没有新增已发布 `sites` 文章。

## 7. 异常处理

- 搜索不足：报告实际独立数和缺口，继续补搜或等待用户调整范围。
- 线上 Ability 暂不可用：保留本地状态，不用本地猜测替代正式库查重结论。
- 单条上传失败：保留其他成功项，不生成第二个批次；修复后重试失败项。
- 重复项或待判重项：进入工作台但不能普通批准。
- 阻断项：进入工作台，等待修改或管理员处理。

## 8. 进度报告

进度报告是工作流的一部分，不是可选说明。至少在以下节点报告：

1. 创建本地任务后。
2. 每累计 20 至 30 条候选并开始或完成一次检查点时。
3. 全任务完整查重开始和结束时。
4. 每完成一组独立候选的字段填充和独立审核时。
5. 审核包生成并暂停等待确认时。
6. 每个上传分片完成、失败或重试时。
7. WordPress 回读核对完成时。

统一报告当前阶段、当前环节、已完成、正在处理和下一步。搜索阶段同时报告发现总数、已排除重复数、待人工判重数、确认独立数和目标数；填充阶段报告应填数、已填数、已审核数和阻断数；上传阶段报告分片数、成功数、复用数、失败数和回读状态。
